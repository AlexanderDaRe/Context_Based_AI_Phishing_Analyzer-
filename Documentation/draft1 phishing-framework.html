02
External Direct-Send Phishing
EXTERNAL
▶
Attack Vector
VEC
Sender spoofs a known external vendor, SaaS provider, or partner organization. Email arrives from outside the simulated org domain. Goal: test whether AI detects spoofed external sender headers, mismatched reply-to, and suspicious infrastructure.
Scenario Types
S-1
Vendor Invoice Lure — Email impersonating a known supplier requesting updated payment details via a link. Target: Claire Fontaine (Finance). High plausibility given her AP role.
S-2
SaaS Password Reset — Spoofed notification from a fake cloud tool (e.g. "DocuSign", "ServiceNow") requesting re-authentication. Target: Both Marcus and Claire. Generic enough to apply broadly.
S-3
HR / Payroll Update — Fake external HR portal asking employee to confirm direct deposit details. Target: Claire. Exploits financial data anxiety.
Sample External Email — Vendor Invoice Lure
FROM: billing@techsupply-invoices.net
REPLY-TO:ar@techsupply-invoices.net
TO: c.fontaine@[simorg].internal
SUBJECT: ACTION REQUIRED: Invoice #INV-2024-0381 — Updated Payment Portal
DATE: [Simulated Date]
Hi Claire,

Please be advised that our payment processing portal has migrated to a new platform. To ensure your next payment processes without delay, we ask that you verify your vendor payment details via the link below before [DATE+3].

[ Verify Payment Details ] <http://techsupply-invoices.net/portal/verify>

If you have any questions, contact your account manager.

Regards,
Accounts Receivable Team
TechSupply Ltd.
Detection Indicators (Feed to AI)
IOC
Sender domain not in known vendor whitelist. Reply-to domain mismatch. No DKIM/SPF alignment. Urgency language + financial action requested. Link domain registered recently.
03
Internal Trust-Based Phishing
INTERNAL
▶
Trust Relationship Model
TRS
Marcus Webb (IT) has an established communication pattern with Claire Fontaine (Finance). Routine requests include system access resets, drive permission changes, and MFA prompts. This trust relationship is the primary exploitation vector for internal phishing.
TRS
Emails from Marcus to Claire arrive from a legitimate internal domain, pass SPF/DKIM, and match historical communication patterns — making technical detection harder and contextual AI analysis critical.
Scenario Types
S-4
IT Credential Reset Request — Marcus sends Claire a link to a fake internal IT portal to reset her ERP credentials due to a "security audit." Exploits IT authority + urgency. Claire expects this type of request.
S-5
Shared Document Lure — Marcus sends a link to a fake SharePoint/OneDrive document requesting Claire review and sign off on an "infrastructure cost report." Exploits normal file-sharing workflow between IT and Finance.
S-6
MFA Fatigue + Callback — Marcus emails Claire that she will receive an MFA push as part of a "routine security check" and to approve it. Primes target to approve a real MFA push. Tests behavioral conditioning.
S-7
Impersonation Escalation — Attacker-controlled Marcus account emails Claire claiming her manager has approved an urgent wire transfer and asks her to initiate via a linked portal. BEC-style attack. High financial impact scenario. Tests multi-authority trust exploitation.
Sample Internal Email — IT Credential Reset
FROM: m.webb@[simorg].internal
TO: c.fontaine@[simorg].internal
SUBJECT: URGENT: ERP Access Reset Required — Security Compliance Window Closes Today
DATE: [Simulated Date]
Hi Claire,

As part of our quarterly security compliance review, IT is resetting ERP credentials for all Finance users today. You will need to reset your password before 5:00 PM or your account will be temporarily suspended pending manual review.

Please use the internal IT portal to complete this now:
[ Reset ERP Credentials ] <http://it-helpdesk.[simorg].internal/reset>

Let me know if you run into any issues — happy to jump on a call.

Thanks,
Marcus Webb
Senior IT Infrastructure Analyst
Detection Indicators (Feed to AI)
IOC
Unusual urgency in normally routine IT communication. Credential action requested via link rather than standard IT ticketing. Timing anomaly (outside business hours or new behavior for Marcus). Link destination inconsistent with known IT portal URL patterns.
IOC
Contextual AI flag: Marcus has not sent credential-related links to Claire in simulated communication history. Writing style delta detectable via baseline behavioral model.
04
AI Detection & Analysis Pipeline
BOTH VECTORS
▶
Layer 1 — Technical Header Analysis
L1
SPF / DKIM / DMARC alignment check. Flag mismatches between From, Reply-To, and Return-Path.
L1
Sender domain age lookup and reputation scoring. Geo-IP analysis on sending server.
L1
Embedded URL extraction and domain analysis: homoglyph detection, newly registered domains, URL redirects.
Layer 2 — Metadata & Behavioural Analysis
L2
Sender-recipient communication frequency baseline. Flag first-contact or low-frequency sender requesting high-risk actions.
L2
Send-time anomaly detection: emails outside normal working patterns for the sender persona.
L2
Attachment type and metadata inspection if applicable.
Layer 3 — Ollama / LLM Contextual Analysis
L3
Full email body passed to LLM for contextual risk scoring. Prompt includes: sender role, recipient role, communication history context, and email body. LLM asked to assess: urgency manipulation, authority exploitation, request type risk, and writing style anomalies.
L3
Writing style baseline comparison for internal senders (Marcus). Deviation from established patterns triggers elevated risk flag.
L3
Multi-factor risk score output: Technical Risk (L1) + Behavioural Risk (L2) + Contextual Risk (L3) = Composite Phishing Confidence Score.

05
Escalating Scenario Testing
INTERNAL
▶
Escalation Logic
ESC
Start with low-suspicion internal emails (Marcus to Claire, routine-looking). Gradually introduce anomalies: urgency, unusual link, credential request, financial action. Tests AI detection sensitivity and false-positive rate at each escalation tier.
ESC
Each tier logged with AI confidence score. Track at which escalation level the AI correctly flags vs. misses.
Escalation Tiers
Tier Scenario Anomaly Level Expected Detection Risk
T0 Routine IT update email, no link None (baseline) Not flagged LOW
T1 IT email with internal link to known portal Minimal Not flagged LOW
T2 IT email with urgency + credential reset link Moderate AI flags L2+L3 MED
T3 IT email with unknown link + financial action High AI flags all layers HIGH
T4 BEC-style wire transfer request via Marcus Critical Maximum risk score HIGH
